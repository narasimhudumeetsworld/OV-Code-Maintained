# Coding Standards

These coding standards apply to all code in the OV-Code-Maintained project, whether written by humans or generated by AI.

## General Principles

### 1. Readability First

Code is read more often than it is written. Optimize for readability:

- Use descriptive names
- Write self-documenting code
- Add comments for complex logic
- Keep functions focused and small

### 2. Consistency

Maintain consistent style throughout the codebase:

- Follow established patterns
- Use the same conventions everywhere
- Match the style of surrounding code

### 3. Simplicity

Prefer simple solutions:

- Avoid premature optimization
- Don't over-engineer
- Solve the problem at hand

## Naming Conventions

| Type | Convention | Example |
|------|------------|---------|
| Variables | camelCase (JS) / snake_case (Python) | `userName` / `user_name` |
| Functions | camelCase (JS) / snake_case (Python) | `getUser()` / `get_user()` |
| Classes | PascalCase | `UserService` |
| Constants | SCREAMING_SNAKE_CASE | `MAX_RETRIES` |
| Files | kebab-case (JS) / snake_case (Python) | `user-service.ts` / `user_service.py` |

## Documentation Standards

### Docstrings (Python)

Use Google-style docstrings:

```python
def calculate_total(items: list[Item], tax_rate: float = 0.1) -> float:
    """Calculate the total price including tax.
    
    This function sums all item prices and applies the specified tax rate.
    
    Args:
        items: List of items to calculate.
        tax_rate: Tax rate as decimal (default: 0.1 for 10%).
        
    Returns:
        Total price including tax.
        
    Raises:
        ValueError: If items list is empty.
        
    Example:
        >>> items = [Item(price=10), Item(price=20)]
        >>> calculate_total(items, 0.1)
        33.0
    """
```

### JSDoc (JavaScript/TypeScript)

```typescript
/**
 * Calculate the total price including tax.
 * 
 * @param items - List of items to calculate
 * @param taxRate - Tax rate as decimal (default: 0.1)
 * @returns Total price including tax
 * @throws {Error} If items array is empty
 * 
 * @example
 * const items = [{ price: 10 }, { price: 20 }];
 * calculateTotal(items, 0.1); // 33.0

```

## Error Handling

### Always Handle Errors

```python
# Good
try:
    result = risky_operation()
except SpecificError as e:
    logger.error(f"Operation failed: {e}")
    raise CustomError("Operation failed") from e

# Bad
try:
    result = risky_operation()
except:  # Never use bare except
    pass   # Never silently ignore errors
```

### Use Custom Exceptions

```python
class UserNotFoundError(Exception):
    """Raised when a user cannot be found."""
    
    def __init__(self, user_id: str):
        self.user_id = user_id
        super().__init__(f"User {user_id} not found")
```

## Testing Standards

### Test Organization

```
tests/
├── unit/           # Fast, isolated tests
├── integration/    # Tests with external dependencies
├── e2e/            # End-to-end tests
└── fixtures/       # Test data
```

### Test Naming

```python
# Good
def test_create_user_with_valid_data_returns_user():
    pass

def test_create_user_with_invalid_email_raises_validation_error():
    pass

# Bad
def test_user():
    pass
```

### Test Coverage

- Minimum coverage: 80%
- Critical paths: 100%
- Edge cases: Document and test

## Security Standards

1. **Never commit secrets** to version control
2. **Validate all input** from external sources
3. **Use parameterized queries** for database operations
4. **Sanitize output** to prevent XSS
5. **Use HTTPS** for all external communications
6. **Apply principle of least privilege**

## Performance Guidelines

1. **Profile before optimizing**
2. **Use appropriate data structures**
3. **Avoid N+1 queries**
4. **Cache expensive operations**
5. **Use async where appropriate**
